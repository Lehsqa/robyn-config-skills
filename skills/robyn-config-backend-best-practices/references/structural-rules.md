## Project Detection

Every project generated by `robyn-config` contains:

```toml
[tool.robyn-config]
design = "ddd"  # or "mvc"
orm = "sqlalchemy"  # or "tortoise"
package_manager = "uv"  # or "poetry"
```

**Rule:** Always check `[tool.robyn-config]` in `pyproject.toml` before making changes. The design and ORM determine the file structure and import paths.

## DDD Architecture Rules

### DDD Layer Responsibilities

```
presentation/  →  HTTP routes, request/response contracts
     ↓ calls
operational/   →  Use-case orchestration (business workflows)
     ↓ calls
domain/        →  Entities, repository interfaces, domain services
     ↓ implements
infrastructure/ → Database, cache, mailing, app factory
```

**Flow:** `Request → presentation → operational → domain → infrastructure`

**Key rules:**
- `presentation` knows ONLY about `operational` (imports) and `infrastructure.application` (for Response, JSON_HEADERS)
- `operational` knows about `domain` (entities, services) and `infrastructure` (repositories, transactions, cache, mailing)
- `domain` knows ONLY about `infrastructure.application` (for InternalEntity, PrimaryKey) and `infrastructure.database` (for transaction)
- `infrastructure` is the bottom layer — it knows about everything but nothing imports it from above

### DDD File Structure

```
│       │   ├── base.py
│       │   └── users.py
│       ├── tables/
│       │   ├── __init__.py
│       │   ├── base.py
│       │   ├── authentication.py
│       │   └── news_letter_subscriptions.py
│       └── migrations/
│           └── env.py
├── operational/              # Use-case orchestration
│   ├── __init__.py
│   ├── users.py              # User use cases
│   └── authentication.py     # Auth use cases

    ├── __init__.py           # Route registration
    ├── _helpers.py           # Shared helpers
    ├── healthcheck.py        # Health check route
    ├── users/
    │   ├── __init__.py
    │   ├── contracts.py      # Request/response Pydantic models
    │   └── rest.py           # Route handlers
    └── authentication/
        ├── __init__.py
        ├── contracts.py
        └── rest.py
```

**Rules:**
- `infrastructure/application/entities/base.py` is rendered from `base.py.jinja2` at project creation time — contains `PrimaryKey`, `InternalEntity`, `PublicEntity`, `PublicSnakeCaseEntity`
- `infrastructure/application/entities/mixins.py` contains `TimeStampMixin`
- `infrastructure/application/entities/response.py` contains `Response`, `ResponseMulti`, `JSON_HEADERS`, `ErrorType`, `ErrorDetail`, `ErrorResponse`
- `infrastructure/application/__init__.py` re-exports everything from `entities/`, `errors/`, and `factory.create()`
- `infrastructure/application/entities/__init__.py` re-exports from `base`, `mixins`, `response`
- Import path: `from ...infrastructure.application import InternalEntity, PrimaryKey, TimeStampMixin` (goes through re-exports)

### DDD Code Examples

#### Domain Entities (`domain/users/entities.py`)

```python
"""User domain entities."""

from pydantic import EmailStr, field_validator

from ...infrastructure.application import (
    InternalEntity,
    PrimaryKey,
    TimeStampMixin,
)
from ...infrastructure.authentication import AuthProvider
from .constants import Role


class UserUncommitted(InternalEntity):
    """Entity for creating a new user."""

    username: str
    email: EmailStr
    password: str
    role: int
    is_active: bool = False
    auth_provider: AuthProvider = AuthProvider.INTERNAL

    @field_validator("role", mode="before")
    @classmethod
    def role_validator(cls, value: int) -> int:
        if value not in Role.values():
            raise ValueError(f"Unsupported role: {value}")
        return value


class UserFlat(UserUncommitted, TimeStampMixin):
    """Full user entity with database fields."""

    id: PrimaryKey


class PasswordForgot(InternalEntity):
    """Entity for password reset request."""

    email: EmailStr


class EmailChange(InternalEntity):
    """Entity for email change confirmation."""

    user_id: PrimaryKey
    email: EmailStr
```

**Rules:**
- Use `InternalEntity` for entities with sensitive data (passwords, tokens)
- Use `PublicEntity` for entities exposed to API responses
- Use `TimeStampMixin` for entities with `created_at`/`updated_at`
- Use `PrimaryKey` type alias for ID fields
- Validators use `@field_validator` and `@model_validator` decorators

#### Repository Interface (`domain/users/repository.py`)

```python
"""User repository interface."""

from __future__ import annotations

from abc import ABC, abstractmethod
from typing import Any, AsyncGenerator

from ...infrastructure.application import PrimaryKey
from .entities import UserFlat, UserUncommitted


class UsersRepository(ABC):
    """Abstract repository contract for user persistence operations."""

    @abstractmethod
    async def all(self) -> AsyncGenerator[UserFlat, None]:
        """Return every user instance."""

    @abstractmethod
    async def get(self, id_: PrimaryKey) -> UserFlat:
        """Return a specific user by identifier."""

    @abstractmethod
    async def get_by_login(self, login: str) -> UserFlat:
        """Return a user matching a login credential."""

    @abstractmethod
    async def create(self, schema: UserUncommitted) -> UserFlat:
        """Persist a new user from the provided schema."""

    @abstractmethod
    async def update(
        self, attr: str, value: Any, payload: dict[str, Any]
    ) -> UserFlat:
        """Update an existing user."""
```

**Rules:**
- Repository interfaces are ABCs with `@abstractmethod`
- Return domain entities (Pydantic models), not database tables
- Use `AsyncGenerator` for `all()` methods
- Use `PrimaryKey` for ID parameters

#### Infrastructure Repository (`infrastructure/sqlalchemy/repository/users.py`)

```python
"""SQLAlchemy repository implementation for Users."""

from typing import Any, AsyncGenerator

from ....domain.users import UsersRepository as UsersRepositoryInterface
from ....domain.users.entities import UserFlat, UserUncommitted
from ..tables import UsersTable
from .base import BaseRepository


class UsersRepository(BaseRepository[UsersTable], UsersRepositoryInterface):
    """SQLAlchemy implementation of UsersRepository."""

    async def all(self) -> AsyncGenerator[UserFlat, None]:
        async for instance in self._all():
            yield UserFlat.model_validate(instance)

    async def get(self, id_: int) -> UserFlat:
        instance = await self._get(key="id", value=id_)
        return UserFlat.model_validate(instance)

    async def get_by_login(self, login: str) -> UserFlat:
        instance = await self._get(key="username", value=login)
        return UserFlat.model_validate(instance)

    async def create(self, schema: UserUncommitted) -> UserFlat:
        instance = await self._save(schema.model_dump())
        return UserFlat.model_validate(instance)

    async def update(
        self, attr: str, value: Any, payload: dict[str, Any]
    ) -> UserFlat:
        schema = await self._update(attr, value, payload)
        return UserFlat.model_validate(schema)
```

**Rules:**
- Inherit from both `BaseRepository[TableName]` AND the domain interface
- Convert table rows to domain entities using `Entity.model_validate(instance)`
- Use `schema.model_dump()` to convert entities to dicts for database operations
- Never expose table objects outside the repository

#### Operational Service (`operational/users.py`)

```python
"""Application services orchestrating domain + infrastructure."""

from typing import Any

from ..domain.users import UserFlat
from ..domain.users import services as users_services
from ..infrastructure.application import PrimaryKey
from ..infrastructure.database import transaction
from ..infrastructure.database.repository import (
    UsersRepository as InfrastructureUsersRepository,
)

__all__ = (
    "create",
    "get_by_login",
    "activate",
    "password_change",
    "password_reset",
)


async def create(payload: dict[str, Any]) -> UserFlat:
    """Create user with activation email."""
    from ..infrastructure.authentication import pwd_context
    from ..infrastructure.cache import CacheRepository
    from ..infrastructure.mailing import EmailMessage, mailing_service
    from ..config import settings

    plain_password = payload.pop("password")
    payload["password"] = pwd_context.hash(plain_password, scheme="bcrypt")

    user = await users_services.create(
        payload=payload,
        repository_factory=InfrastructureUsersRepository,
    )

    activation_key = users_services.generate_key(user.email)
    activation_link = users_services.create_activation_link(activation_key)

    async with CacheRepository[UserFlat]() as cache:
        await cache.set(
            namespace="activation",
            key=activation_key,
            instance=user,
            ttl=settings.cache.ttl_activation_seconds or None,
        )

    await mailing_service.send(
        EmailMessage(
            recipients=[user.email],
            subject="Account activation",
            body=f"Activation link: {activation_link}",
        )
    )

    return user


async def get_by_login(login: str) -> UserFlat:
    """Get user by username or email."""
    async with transaction():
        return await InfrastructureUsersRepository().get_by_login(login=login)
```

**Rules:**
- Operational services orchestrate domain services + infrastructure
- Use `async with transaction():` for database operations
- Import infrastructure repositories explicitly from `infrastructure.database.repository`
- Use `__all__` to export public functions
- Cache operations use `async with CacheRepository[Entity]():` context manager
- Mailing uses `mailing_service.send(EmailMessage(...))`

#### Presentation Contracts (`presentation/users/contracts.py`)

```python
"""User request/response contracts."""

from typing import Annotated

from app.infrastructure.application import (
    PrimaryKey,
    PublicEntity,
)
from pydantic import EmailStr, Field


class UserCreateBody(PublicEntity):
    """Request body for creating a user."""

    username: Annotated[
        str,
        Field(description="User username", examples=["john"], min_length=1, max_length=255),
    ]
    email: Annotated[
        EmailStr,
        Field(description="User email", examples=["john@email.com"]),
    ]
    password: Annotated[
        str,
        Field(description="User password", examples=["@Dm1n#LKJ"]),
    ]


class UserPublic(PublicEntity):
    """Public user response model."""

    id: Annotated[PrimaryKey, Field(description="User id")]
    username: Annotated[str, Field(description="User username")]
    email: Annotated[EmailStr, Field(description="User email")]
    is_active: Annotated[bool, Field(description="Whether user activated")]
    role: Annotated[int, Field(description="User role")]
```

**Rules:**
- Use `PublicEntity` as base for all request/response models
- Use `Annotated` with `Field` for OpenAPI documentation
- Use `EmailStr` for email fields
- Never expose `password` in `*Public` models
- Add `examples` in Field for API documentation

#### Presentation Routes (`presentation/users/rest.py`)

```python
"""User REST API routes."""

from robyn import Request, Response as RobynResponse, Robyn

from ...infrastructure.application import (
    JSON_HEADERS,
    Response,
    parse_primary_key,
)
from ...operational import users as users_ops
from .contracts import UserCreateBody, UserPublic


def register(app: Robyn) -> None:
    """Register user routes."""

    @app.post("/users", openapi_name="Create User", openapi_tags=["Users"])
    async def user_create(body: UserCreateBody) -> RobynResponse:
        """Create a new user."""
        user = await users_ops.create(payload=body.model_dump())
        payload = Response[UserPublic](result=UserPublic.model_validate(user))
        return RobynResponse(
            status_code=201,
            headers=JSON_HEADERS,
            description=payload.model_dump_json(),
        )

    @app.get("/users/:id", openapi_name="Get User", openapi_tags=["Users"])
    async def user_get(request: Request) -> Response[UserPublic]:
        """Get a user by ID."""
        id_ = parse_primary_key(request.path_params["id"])
        user = await users_ops.get(id_=id_)
        return Response[UserPublic](result=UserPublic.model_validate(user))

    @app.post(
        "/users/password/change",
        auth_required=True,
        openapi_name="Change Password",
        openapi_tags=["Users"],
    )
    async def user_password_change(
        request: Request, body: PasswordChangeBody
    ) -> Response[UserPublic]:
        """Change user password."""
        from ...operational import authentication as auth_ops

        user_id = auth_ops.require_user_id(request)
        user = await users_ops.get(user_id=user_id)
        updated = await users_ops.password_change(
            user=user,
            old_password=body.old_password,
            new_password=body.new_password,
        )
        return Response[UserPublic](result=UserPublic.model_validate(updated))
```

**Rules:**
- Use `register(app: Robyn)` function pattern (NOT direct app decorator usage)
- Use `Response[Model]` for generic responses, `RobynResponse` for status code control
- Use `JSON_HEADERS` from `infrastructure.application`
- Use `parse_primary_key(request.path_params["id"])` for ID extraction
- Use `auth_required=True` for protected endpoints
- Use `auth_ops.require_user_id(request)` to get authenticated user ID
- Always include `openapi_name` and `openapi_tags` for API documentation
- Return `RobynResponse(status_code=201)` for creation, `202` for async operations, `200` for success

#### Route Registration (`presentation/__init__.py`)

```python
"""Presentation layer route registration."""

from robyn import Robyn

from . import authentication, healthcheck, users


def register_routes(app: Robyn) -> None:
    """Register all presentation routes."""
    healthcheck.register(app)
    users.register(app)
    authentication.register(app)
```

**Rules:**
- Import entire modules (`from . import authentication, healthcheck, users`)
- Use `register_routes(app: Robyn)` as the main registration function
- Order matters: healthcheck first, then business modules, then auth last
- Each module must have a `register(app: Robyn)` function
- When `robyn-config add` creates a new entity, it appends the module import and `module.register(app)` call

#### App Construction (`server.py`)

```python
"""DDD application entry point."""

from app.config import settings
from app.infrastructure.application import error_response, middlewares
from app.infrastructure.application.factory import create
from app.operational.authentication import JWTAuthenticationHandler
from app.presentation import register_routes
from robyn import Robyn
from robyn.openapi import Components, OpenAPI, OpenAPIInfo

app: Robyn = create(
    __name__,
    route_registrars=(register_routes,),
    middlewares=(
        middlewares.sessions.register,
        middlewares.cors.register,
    ),
    exception_handler=error_response,
    authentication_handler=JWTAuthenticationHandler(),
    openapi=OpenAPI(
        info=OpenAPIInfo(
            title=settings.public_api.name,
            version=settings.public_api.version,
            components=Components(
                securitySchemes={
                    "BearerAuth": {
                        "type": "http",
                        "scheme": "bearer",
                        "bearerFormat": "JWT",
                    }
                }
            ),
        ),
    ),
)

if __name__ == "__main__":
    app.start(host="0.0.0.0", port=8000)
```

**Rules:**
- DDD uses `create()` from `infrastructure.application.factory` (app factory pattern)
- MVC constructs `Robyn(__file__)` directly and configures it inline
- `route_registrars` receives tuple of registration functions
- `middlewares` receives tuple of middleware registration functions
- `exception_handler` is `error_response` from `infrastructure.application`
- `authentication_handler` is `JWTAuthenticationHandler` from `operational.authentication`
- OpenAPI config is passed to `create()` with `BearerAuth` security scheme
- Always set `app.openapi.openapi_spec["security"] = [{"BearerAuth": []}]` after creation

### DDD Adding New Entity

When adding a new entity (e.g., `product`), use:

```bash
robyn-config add product
```

This generates:
- `domain/product/__init__.py` — domain package
- `domain/product/entities.py` — `ProductUncommitted`, `ProductFlat`
- `domain/product/repository.py` — `ProductRepository` interface
- `infrastructure/sqlalchemy/product_table.py` — `ProductTable`
- `infrastructure/sqlalchemy/repository/product.py` — `ProductRepository` implementation
- `operational/product.py` — `get_all`, `get`, `create`, `update`, `delete`
- `presentation/product/__init__.py` — presentation package
- `presentation/product/contracts.py` — `ProductCreateBody`, `ProductUpdateBody`, `ProductPublic`
- `presentation/product/rest.py` — CRUD routes with `register(app)`

After generation:
1. Run migrations: `make makemigration` (SQLAlchemy) or `make migrate` (Tortoise)
2. Verify routes are registered in `presentation/__init__.py`
3. Verify repository exports in `infrastructure/sqlalchemy/repository/__init__.py`
4. Verify table exports in `infrastructure/sqlalchemy/tables/__init__.py`

## MVC Architecture Rules

### MVC Layer Responsibilities

```
views/     →  HTTP routes, contracts, business logic
   ↓ calls
models/    →  Database tables, repositories, transactions
   ↓ uses
config/    →  Settings
middlewares/ →  CORS, sessions
utils.py   →  Shared helpers
```

**Flow:** `Request → views → models → database`

**Key rules:**
- `views` contains ALL business logic (unlike DDD where it's in operational/domain)
- `models` is the only persistence layer
- `utils.py` provides shared helpers (JSON responses, error classes)
- `urls.py` registers all routes

### MVC File Structure

```
src/app/
├── schemas.py                 # (from .jinja2) PrimaryKey, PublicEntity, InternalEntity, Response, UserFlat, UserUncommitted
├── config/                    # Settings (same structure as DDD)

│   ├── core.py
│   ├── database.py
│   ├── cache.py
│   ├── mailing.py
│   ├── authentication.py
│   ├── cors.py
│   ├── logging.py
│   ├── public_api.py
│   └── integrations/
│       └── frontend.py
├── models/                    # Persistence layer
│   ├── __init__.py
│   ├── sqlalchemy/            # (or tortoise/)
│   │   ├── __init__.py
│   │   ├── database.py        # Database engine/session
│   │   ├── models.py          # Re-exports all tables
│   │   ├── repository.py      # BaseRepository + UsersRepository
│   │   ├── tables/
│   │   │   ├── __init__.py

│       ├── __init__.py
│       ├── database.py
│       ├── models.py
│       ├── repository.py
│       └── tables/
├── views/                     # HTTP routes + business logic
│   ├── __init__.py

│   ├── contracts.py           # Shared request/response models
│   ├── healthcheck.py         # Health check
│   ├── helpers.py             # View helpers
│   └── users.py               # User routes + logic
├── middlewares/
│   ├── __init__.py
│   ├── cors.py
│   └── sessions.py
├── utils.py                   # JSON response, error classes, constants
```

**Rules:**
- `schemas.py` is at project root (rendered from `schemas.py.jinja2`) — contains ALL entity definitions AND response wrappers
- `models/sqlalchemy/tables/base.py` is rendered from `.jinja2` at generation time
- `views/contracts.py` contains shared request/response models (login, password, activation, etc.)
- `utils.py` contains `JSON_HEADERS`, `json_response()`, `NotFoundError`, `DatabaseError`, `UnprocessableError`

### MVC Code Examples

#### View with Business Logic (`views/users.py`)

```python
"""User views with routes and business logic."""

from robyn import Request, Response as RobynResponse, Robyn

from ..models import UsersRepository, transaction
from ..schemas import (
    PrimaryKey,
    PublicEntity,
    Response,
    ResponseMulti,
    parse_primary_key,
)
from ..utils import JSON_HEADERS


class UserPublic(PublicEntity):
    """Public user response model."""

    id: PrimaryKey
    username: str
    email: str
    is_active: bool
    role: int


def register(app: Robyn) -> None:
    """Register user routes."""

    @app.get("/users", openapi_name="List Users", openapi_tags=["Users"])
    async def user_list(request: Request) -> ResponseMulti[UserPublic]:
        """Get all users."""
        async with transaction():
            repo = UsersRepository()
            items = [item async for item in repo.all()]
        return ResponseMulti[UserPublic](
            result=[UserPublic.model_validate(item) for item in items]
        )

    @app.get("/users/:id", openapi_name="Get User", openapi_tags=["Users"])
    async def user_get(request: Request) -> Response[UserPublic]:
        """Get a user by ID."""
        id_ = parse_primary_key(request.path_params["id"])
        async with transaction():
            repo = UsersRepository()
            item = await repo.get(id_=id_)
        return Response[UserPublic](result=UserPublic.model_validate(item))

    @app.post("/users", openapi_name="Create User", openapi_tags=["Users"])
    async def user_create(body: UserCreateBody) -> RobynResponse:
        """Create a new user."""
        async with transaction():
            repo = UsersRepository()
            item = await repo.create(body.model_dump())
        payload = Response[UserPublic](result=UserPublic.model_validate(item))
        return RobynResponse(
            status_code=201,
            headers=JSON_HEADERS,
            description=payload.model_dump_json(),
        )
```

**Rules:**
- Business logic lives IN the view (unlike DDD where it's in operational)
- Use `async with transaction():` for ALL database operations
- Use `UsersRepository()` directly in views
- Return `ResponseMulti[Model]` for list endpoints, `Response[Model]` for single
- Use `RobynResponse(status_code=201)` for creation
- Import `schemas` from project root (`..schemas`), NOT from models/
- `schemas.py` is rendered from `schemas.py.jinja2` at project creation time
- `contracts.py` in views contains shared request/response models (login, password change, etc.)

**Rules:**
- Business logic lives IN the view (unlike DDD where it's in operational)
- Use `async with transaction():` for ALL database operations
- Use `UsersRepository()` directly in views
- Return `ResponseMulti[Model]` for list endpoints, `Response[Model]` for single
- Use `RobynResponse(status_code=201)` for creation

#### Repository (`models/sqlalchemy/repository.py`)

```python
"""SQLAlchemy repository implementation."""

from typing import Any, AsyncGenerator, Generic, get_args, get_origin

from sqlalchemy import asc, delete, desc, func, select, update
from sqlalchemy.engine import Result

from ..schemas import UserFlat, UserUncommitted
from ..utils import DatabaseError, NotFoundError, UnprocessableError
from .database import Session
from .tables import ConcreteTable, UsersTable


class BaseRepository(Session, Generic[ConcreteTable]):
    """Base repository with CRUD operations."""

    schema_class: type[ConcreteTable] | None = None

    def __init__(self) -> None:
        super().__init__()
        if not getattr(self, "schema_class", None):
            raise UnprocessableError(message="schema_class is required")

    # ... CRUD methods ...


class UsersRepository(BaseRepository[UsersTable]):
    """User repository implementation."""

    schema_class = UsersTable

    async def all(self) -> AsyncGenerator[UserFlat, None]:
        async for instance in self._all():
            yield UserFlat.model_validate(instance)

    async def get(self, id_: int) -> UserFlat:
        instance = await self._get(key="id", value=id_)
        return UserFlat.model_validate(instance)

    async def get_by_login(self, login: str) -> UserFlat:
        for field in ("username", "email"):
            try:
                instance = await self._get(key=field, value=login)
                return UserFlat.model_validate(instance)
            except NotFoundError:
                continue
        raise NotFoundError

    async def create(self, payload: dict[str, Any]) -> UserFlat:
        instance = await self._save(payload)
        return UserFlat.model_validate(instance)

    async def update(
        self, attr: str, value: Any, payload: dict[str, Any]
    ) -> UserFlat:
        schema = await self._update(attr, value, payload)
        return UserFlat.model_validate(schema)
```

**Rules:**
- Set `schema_class = TableName` explicitly
- Convert to domain entities using `Entity.model_validate(instance)`
- Use `async with transaction():` in VIEWS, NOT in repositories
- Repositories work with table objects internally, return entities externally

#### Route Registration (`urls.py`)

```python
"""Route registration."""

from robyn import Robyn

from .views import authentication, healthcheck, users


def register_routes(app: Robyn) -> None:
    """Register all routes."""
    users.register(app)
    authentication.register(app)
    healthcheck.register(app)
```

**Rules:**
- Import entire modules (`from .views import authentication, healthcheck, users`)
- Use `register_routes(app: Robyn)` as the main function
- Order: business modules first, then auth, then healthcheck last
- Each module must have a `register(app: Robyn)` function
- When `robyn-config add` creates a new entity, it appends the module import and `module.register(app)` call

#### App Construction (`server.py`)

```python
"""MVC application entry point."""

from app.config import settings
from app.middlewares import cors, sessions
from app.urls import register_routes
from app.utils import error_response
from app.views.authentication import JWTAuthenticationHandler
from robyn import Robyn
from robyn.openapi import Components, OpenAPI, OpenAPIInfo

app = Robyn(
    __file__,
    openapi=OpenAPI(
        info=OpenAPIInfo(
            title=settings.public_api.name,
            version=settings.public_api.version,
            components=Components(
                securitySchemes={
                    "BearerAuth": {
                        "type": "http",
                        "scheme": "bearer",
                        "bearerFormat": "JWT",
                    }
                }
            ),
        ),
    ),
)

app.openapi.openapi_spec["security"] = [{"BearerAuth": []}]

# Configure app
app.exception(error_response)
app.configure_authentication(JWTAuthenticationHandler())

# Middlewares
sessions.register(app)
cors.register(app)

# Register routes
register_routes(app)

if __name__ == "__main__":
    app.start(host="0.0.0.0", port=8000)
```

**Rules:**
- MVC constructs `Robyn(__file__)` directly (no factory pattern)
- DDD uses `create()` from `infrastructure.application.factory`
- Configure exception handler with `app.exception(error_response)`
- Configure authentication with `app.configure_authentication(JWTAuthenticationHandler())`
- Register middlewares explicitly: `sessions.register(app)`, `cors.register(app)`
- Register routes explicitly: `register_routes(app)`
- Always set `app.openapi.openapi_spec["security"] = [{"BearerAuth": []}]` after creation

### MVC Adding New Entity

When adding a new entity (e.g., `product`), use:

```bash
robyn-config add product
```

This generates/updates:
- `models/sqlalchemy/tables/product_table.py` — `ProductTable` class
- `models/sqlalchemy/repository.py` — Appends `ProductRepository` class
- `views/product.py` — Routes + contracts + business logic

After generation:
1. Run migrations: `make makemigration` (SQLAlchemy) or `make migrate` (Tortoise)
2. Verify table is exported in `models/sqlalchemy/tables/__init__.py`
3. Verify repository is imported in `models/sqlalchemy/__init__.py`
4. Verify route is registered in `urls.py`

## Shared Rules

### Settings and Configuration

All projects use `pydantic-settings` with:

```python
class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_prefix="SETTINGS__",
        env_nested_delimiter="__",
        env_file=".env",
        env_file_encoding="utf-8",
    )
```

**Rules:**
- Environment variables use `SETTINGS__` prefix (e.g., `SETTINGS__DATABASE__URL`)
- Nested settings use `__` delimiter (e.g., `SETTINGS__AUTHENTICATION__SECRET`)
- Settings are modular: `config/__init__.py` imports from submodules
- Never hardcode secrets — use environment variables

### Error Handling

**DDD errors** (in `infrastructure/application/errors/`):

```python
class NotFoundError(Exception):
    """Resource not found."""
    status_code: int = 404

class DatabaseError(Exception):
    """Database operation failed."""
    status_code: int = 500

class UnprocessableError(Exception):
    """Invalid request data."""
    status_code: int = 422

class AuthenticationError(Exception):
    """Authentication failed."""
    status_code: int = 401
```

**MVC errors** (in `utils.py`):

```python
class NotFoundError(Exception):
    status_code: int = 404

class DatabaseError(Exception):
    status_code: int = 500

class UnprocessableError(Exception):
    status_code: int = 422

class AuthenticationError(Exception):
    status_code: int = 401
```

**Rules:**
- Errors are mapped to HTTP status codes via exception handlers
- Use `NotFoundError` for missing resources (404)
- Use `UnprocessableError` for validation failures (422)
- Use `AuthenticationError` for auth failures (401)
- Use `DatabaseError` for database failures (500)

### Transaction Boundaries

**DDD** (in `operational/`):

```python
async with transaction():
    repository = UsersRepository()
    user = await repository.create(schema)
    # More operations...
# Auto-commit on success, rollback on exception
```

**MVC** (in `views/`):

```python
async with transaction():
    repo = UsersRepository()
    user = await repo.create(body.model_dump())
    # More operations...
# Auto-commit on success, rollback on exception
```

**Rules:**
- Transactions are context managers with `async with`
- ONE transaction = ONE logical operation (create, update, delete)
- Never share transactions across multiple use cases
- Transaction auto-commits on success, rolls back on exception

### Naming Conventions

| Element | Convention | Example |
|---------|-----------|---------|
| Entity classes | PascalCase | `UserFlat`, `ProductUncommitted` |

### SQLAlchemy

**Session management:**

```python
from sqlalchemy.ext.asyncio import AsyncSession, create_async_engine

# Engine
engine = create_async_engine(settings.database.url, echo=settings.database.echo)

# Session
async_session = async_sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)

async with transaction():
    session = await async_session()
    # Operations...
```

**Table definitions:**

```python
from sqlalchemy.orm import Mapped, mapped_column
from .base import BaseTable

class UsersTable(BaseTable):
    __tablename__ = "users"

    username: Mapped[str] = mapped_column(unique=True, index=True)
    email: Mapped[str] = mapped_column(unique=True, index=True)
    password: Mapped[str | None] = mapped_column()
    is_active: Mapped[bool] = mapped_column(default=False, server_default="0")
```

```bash
make makemigration  # Generate migration
make migrate        # Apply migration
```

## Anti-Patterns

| Anti-Pattern | Why It's Wrong | Correct Approach |
|-------------|---------------|-----------------|
| Importing tables from views | Violates layer boundaries | Use domain entities via repositories |
| Business logic in routes | Hard to test, hard to reuse | Move to operational/domain (DDD) or keep thin (MVC) |
| Direct DB queries in views | Bypasses transaction management | Use `async with transaction():` |
| Returning table objects from API | Leaks database structure | Convert to `PublicEntity` models |
| Hardcoded secrets | Security risk | Use environment variables with `SETTINGS__` prefix |
| Missing `__all__` in operational | Exposes internal functions | Explicitly export public functions |
| Using `dict` responses | No type safety | Use `Response[Model]` or `RobynResponse` |
| Missing OpenAPI tags | Broken API docs | Always add `openapi_name` and `openapi_tags` |
| Skipping migration | Schema drift | Always run `make makemigration` after schema changes |
